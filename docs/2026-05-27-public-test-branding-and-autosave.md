# Public Test Branding, Autosave, Analytics, and Settings Update

Date: 2026-05-27

This note records production behavior added after the earlier Polus and entry-profile documentation. It is product/API documentation only; repository operating rules remain in `AI_GUIDE.md`.

## Public Link Branding

Public links now have optional `publicBranding` stored on `TestPublicLink` as JSON.

Backend/API surfaces:

- Admin create/update/list DTOs accept or expose `publicBranding`.
- Public link access, session state, and result responses expose `publicBranding` so direct `/t/*` URLs render consistently.
- The backend validates the branding config with Zod and stores only the config; it does not upload, fetch, resize, or proxy remote images.

Supported config shape is versioned as `version: 1` and may include:

- page background: `default`, `solid`, or HTTPS image URL with optional overlay;
- up to two HTTPS header logos with alt text and optional `sm`/`md`/`lg` size;
- primary button color and text color;
- card/surface color and border color;
- accent color.

Frontend behavior:

- The admin constructor is available from the public-links workspace for `STANDARD` links.
- "Reset to standard" sends `publicBranding: null` and restores the default public theme.
- `STANDARD` public pages apply branding through `PublicThemeLayout`.
- `POLUS` links ignore `publicBranding`; Polus keeps its own scoped assets/styles.

## Public Session Autosave

The public run workspace autosaves answers before the student explicitly finishes the test.

Behavior:

- Autosave is debounce-based (`900 ms` in the current implementation).
- Manual save and finish actions cancel queued autosaves and wait for in-flight autosaves before continuing.
- Autosave runs for both `STANDARD` and `POLUS` run UIs.
- Student-facing copy should stay human-readable and avoid raw API states.
- On save failure, the UI keeps an actionable error state instead of silently discarding answers.

Relevant frontend files:

- `client/src/widgets/public-test-workspace/ui/use-public-test-run-autosave.ts`
- `client/src/widgets/public-test-workspace/ui/public-test-autosave-status.tsx`
- `client/src/widgets/public-test-workspace/ui/use-public-test-run-workspace.ts`
- `client/src/widgets/public-test-workspace/ui/polus/polus-public-run.tsx`

## Profession Atlas URL

Admin settings now include an optional profession atlas URL.

Backend/API surfaces:

- `GET /admin/settings/profession-atlas`
- `PATCH /admin/settings/profession-atlas`
- Stored setting key: `professionAtlas.url`
- Public result and admin attempt-detail responses can include `professionAtlasUrl`.

Product behavior:

- When configured, result screens may show a profession atlas link for student-facing prof-orientation results.
- The setting is global app configuration, not per-test or per-link branding.

## Test Analytics Report And Export

The analytics workspace is available at `/admin/analytics` and uses protected tests-module endpoints.

Backend/API surfaces:

- `GET /admin/tests/topics/:topicId/analytics/summary`
- `GET /admin/tests/topics/:topicId/analytics/export.xlsx`
- `GET /admin/tests/topics/:topicId/analytics/export.pdf`

Filters include:

- scope;
- public link;
- link status;
- date range.

Exports are binary responses generated by the backend. XLSX sheets include report sections such as summary, directions, public links, groups, demographics, and attempts. PDF export uses the backend renderer service.
