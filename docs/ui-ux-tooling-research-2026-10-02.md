# Инструменты UI/UX для AI_Template

Дата исследования: 2026-10-02. Охват по уточнению пользователя — только UI/UX. Проверены исходники и конфигурации проекта, первичные GitHub-репозитории и документация авторов. Инструменты не устанавливались; их результаты на нашем приложении в этом исследовании не измерялись.

По покрытию проверок у проекта есть конкретные возможности улучшения: автоматический accessibility scan реального экрана, сравнение рендера с визуальным эталоном и систематическое прохождение состояний. Это оценка инструментария, а не заключение о качестве текущего интерфейса или его соответствии всему WCAG.

## Совместимость и поддержка

Сравнение screenshots выполняется в той же среде, где получен эталон: OS, browser, fonts, viewport/DPR и данные фиксируются. Windows-картинка не считается надежным эталоном для Ubuntu CI; это прямо оговорено в [документации Playwright](https://playwright.dev/docs/test-snapshots). Loading/animations стабилизируются осмысленно; динамические области маскируются только при известной причине. Состояния и важные изменения не скрываются ради зеленого результата.

Просмотренные [react-vite package](https://github.com/storybookjs/storybook/blob/next/code/frameworks/react-vite/package.json) и [addon-vitest package](https://github.com/storybookjs/storybook/blob/next/code/addons/vitest/package.json) допускают в peer ranges React 19, Vite 8 и Vitest 5. Однако это ветка next с версиями 11.0.0-alpha.*, не подтверждение совместимости выбранного стабильного выпуска. До внедрения нужны проверка опубликованной версии, ее полного dependency graph и локальный build/test; понижение нашего фиксированного стека ради инструмента не предлагается.

Для axe предусмотрена интеграция непосредственно с Playwright page, поэтому новый browser MCP не обязателен. Это аргумент для короткого пилота, а не утверждение, что установленная у нас комбинация уже испытана. Автоматическая severity инструмента также не заменяет влияние на пользовательский сценарий.

## На чем оценивать практическую пользу

Начальная выборка: /login; admin users с editor sheet; окно создания учебного заведения; публичная регистрация и один экран вопроса. Это существующие интерфейсы и компоненты, а не новая функциональность.

На одинаковом production preview и тестовых данных полезно сравнить:

- Accessibility: исходное состояние, открытый dialog, error/loading; raw axe results и ручная проверка Tab/Shift+Tab/Escape, видимости фокуса, возврата фокуса и keyboard-only выполнения задачи.
- Визуальные эталоны: выбранные desktop и narrow размеры, длинные русские подписи, сохраненный ответ, важные theme/portal состояния. Размеры — условия эксперимента, не универсальные книжные нормы.
- Наблюдение UX: удалось ли человеку без подсказки выполнить нужную задачу, где возникли ошибки и непонимание. Screenshot diff и accessibility score этого не устанавливают.

Полезность нового инструмента определяется воспроизводимыми находками, которые текущая проверка пропускает, уровнем ложных тревог и поддержкой fixtures/baselines. Само количество инструментов, детекторов или зеленых баллов не доказывает «пик» UI/UX.

Практический выбор для проекта сейчас: axe на существующих browser-сценариях, визуальные проверки на той же Playwright-основе и ручной keyboard walkthrough. Storybook — после подтверждения потребности в регулярно используемой витрине. Impeccable — возможное второе мнение с проверкой его оснований. Установка и изменение приложения не выполнялись; это законченный обзор для выбора следующего улучшения.
