# Настраиваемое наименование оператора персональных данных

## Цель

Убрать захардкоженное наименование платформы-оператора персональных данных и дать администратору возможность менять его рядом с глобальной политикой обработки персональных данных.

Настройка применяется только к публичным ссылкам с режимом обработки `PUBLIC`, где оператором является платформа. Для режима обработки от имени учебного заведения продолжает использоваться наименование выбранного учебного заведения.

## Интерфейс администратора

В карточке политики персональных данных добавить обязательное текстовое поле «Наименование оператора персональных данных» перед редактором текста политики.

- Текущее значение по умолчанию: `АНО «Центр развития компьютерного спорта и цифровых технологий»`.
- Значение обрезается по краям, не может быть пустым и ограничивается 512 символами.
- Поле сохраняется той же кнопкой и тем же запросом, что версия, дата публикации и текст политики.
- Ошибки валидации отображаются через существующий механизм ошибок настроек.

## Хранение и совместимость

Поле `operatorFullName` хранится в существующем JSON объекта `AppSetting` с ключом `privacy.policy`. Миграция Prisma не требуется.

Схема чтения принимает старые записи без нового поля и подставляет текущее встроенное значение. После следующего сохранения настройки поле записывается явно. Публичная политика `/privacy` не обязана показывать наименование отдельным полем: оно используется для определения оператора публичных тестов.

## Поток данных

1. Администратор загружает настройки политики вместе с эффективным `operatorFullName`.
2. При сохранении backend валидирует и сохраняет политику и наименование одним согласованным payload.
3. В той же операции backend обновляет `operatorFullNameSnapshot` у существующих `TestPublicLink` с режимом `PUBLIC`.
4. При создании или редактировании публичной ссылки с режимом `PUBLIC` backend берет актуальное глобальное наименование вместо константы.
5. Публичный ответ продолжает передавать имя через существующий объект `personalData`.
6. Оба шаблона, `STANDARD` и `POLUS`, автоматически показывают новое имя через общий компонент `PublicPersonalDataOperator`.

## Исторические данные

Изменение настройки обновляет действующие публичные ссылки, чтобы новое имя появилось без ручного пересохранения каждой ссылки.

Снимки оператора в уже созданных попытках не изменяются. Это сохраняет фактические юридические данные, действовавшие в момент начала попытки. Новые попытки получают обновленный снимок из публичной ссылки.

## Ошибки и атомарность

Сохранение `AppSetting` и обновление публичных ссылок выполняются в одной транзакции. Если одна из операций завершается ошибкой, ни настройка, ни ссылки не должны оставаться частично обновленными.

Пустое или слишком длинное наименование отклоняется до записи в базу. Поврежденная старая настройка продолжает приводить к существующему fallback всей политики.

## Тестирование

Backend:

- старый JSON без `operatorFullName` возвращает встроенное значение;
- сохранение нормализует и возвращает новое имя;
- сохранение обновляет только публичные ссылки с режимом `PUBLIC`;
- ссылки учебных заведений и существующие попытки не изменяются;
- создание и смена режима ссылки на `PUBLIC` используют актуальное имя;
- DTO отклоняет пустое и слишком длинное значение.

Frontend:

- поле отображается рядом с политикой и заполняется текущим значением;
- изменение поля попадает в payload сохранения;
- оба публичных шаблона отображают имя из `personalData` без дополнительной шаблонной логики.

Приемочная браузерная проверка:

- изменить имя в админке и сохранить;
- открыть существующую публичную ссылку платформы-оператора в шаблонах `STANDARD` и `POLUS`;
- убедиться, что оба показывают новое имя;
- открыть ссылку учебного заведения и убедиться, что она показывает собственное наименование;
- вернуть исходное тестовое значение после проверки, если проверка выполнялась на общей среде.
